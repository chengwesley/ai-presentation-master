# 從規格到產出：頁面規格卡與工具交接格式

## 這份文件解決什麼問題

`11-visual-forms.md` 和 `12-layout-system.md` 能決定「這頁該畫成什麼、用哪個版型」，但決定完之後有一個斷點：**規格在對話裡，產出在另一個工具裡。**

實際會發生的事：
- 使用者拿到「這頁是因果鏈，畫成箭頭鏈，強調第二個節點」，然後打開 Gamma 輸入「請幫我做一頁因果關係圖」——Gamma 產出一張等權三卡片，強調不見了。
- 用 open-slide 寫 code 時，規格只說「流程圖」，於是寫成 flex 卡片橫排，該有的連線沒有。
- 交給設計同事排版，節點文字被順手潤飾成更「順」的說法，斷言變成廢話。

共同原因是**規格從對話翻譯到工具時，被降維成一句籠統的形容**。這份文件給一個固定欄位的中介格式，以及三種目標工具的翻譯規則。

**什麼時候用**：使用者已經想清楚內容與視覺形式，要開始「做出來」的時候（步驟 6 之後、步驟 7 到 10 之間）。如果內容還沒收斂，先回 `01`／`02`，不要急著填規格卡。

## 一、頁面規格卡（中介格式）

一頁一張卡。欄位固定，**不要因為某頁「沒什麼特別的」就省略欄位**——省掉的欄位就是產出工具會自由發揮的地方。

```yaml
page: 7
question: 為什麼現在的流程會漏單？          # 這頁要回答的唯一問題
message: 漏單不是人員疏失，是三個系統之間沒有交接點   # 一句可被反駁的斷言
relation: 因果                              # 見 11 §1：順序／組成／對立／因果／交集／程度／單一
form: 箭頭鏈（左→右三節點）                  # 見 11 §2 概念圖解庫
layout: 2 左文右圖                          # 見 12 §1 版型庫編號＋名稱
nodes:                                      # 逐字。不要潤飾、不要補「等等」
  - 業務系統收單
  - ❗人工轉貼到 ERP                          # 焦點節點
  - 倉儲系統出貨
focus: nodes[1]                             # 全頁唯一焦點
color:
  accent: nodes[1]                          # 只有焦點用強調色
  neutral: [nodes[0], nodes[2]]             # 其餘一律中性階
geometry: 三節點等距                         # 若有比例訊息，寫死比例（見下方陷阱 3）
script: |                                    # 講者這頁要說的話（決定密度）
  這裡有三個系統。前後兩個都是自動的，中間這一步是人工複製貼上。
  漏單全部發生在這一步——不是誰不小心，是這裡本來就沒有交接機制。
forbid:                                     # 明確禁止事項
  - 不要加圖示（三個都是抽象系統，見 11 §5）
  - 不要加圖例（用標註）
  - 不要把三個節點做成等權卡片
```

### 為什麼一定要有 `forbid` 欄位

產出工具（尤其 Gamma、Napkin 這類自動生成，以及 LLM 寫 code）**預設會加裝飾、會把並列元素做成等權、會補圖示**。這不是 bug，是它們的訓練目標——「看起來完整」。

規格沒寫禁止的地方，就等於默許。`forbid` 是唯一能把 `11`／`12` 的紀律帶過交接線的欄位。

### 最小可用版本

時間不夠時，至少要有這四欄，其他可略：

| 欄位 | 少了會發生什麼 |
|---|---|
| `message` | 產出一頁沒有主張的資訊整理 |
| `relation` | 退回條列 |
| `nodes`（逐字） | 文字被改寫，斷言變廢話 |
| `focus` | 三個元素等權，觀眾不知道看哪裡 |

`layout`／`color`／`geometry`／`forbid` 是「品質欄位」——影響的是成品像專業還是像草稿。

## 二、三種目標工具的翻譯規則

同一張規格卡，翻成三種東西。差別在於**你能控制到多細**。

| | open-slide／HTML deck（寫 code） | Gamma／Napkin（自動生成） | Canva／PPTX（人工排） |
|---|---|---|---|
| 控制力 | 完全可控（座標級） | 只能引導，不能指定 | 完全可控但靠人執行 |
| 規格翻成 | 元件選擇 ＋ 座標 | 一段 prompt | 一張 checklist ＋ 數值 |
| `layout` 欄位 | 直接對應元件 | **改寫成禁止句**（它會自己選版型） | 直接照做 |
| `nodes` | 直接貼字串 | 標「以下文字逐字使用，不要改寫」 | 複製貼上，禁止手改 |
| `geometry` | 寫死座標／比例 | 用文字描述比例，然後**檢查它有沒有做到**（常做不到） | 用尺標對齊 |
| 最容易掉的 | 連線關係（寫成 flex 卡片） | 焦點與比例 | 節點文字被潤飾 |

### 翻給 open-slide／HTML deck

判斷順序（不要跳過第一步）：

1. **`relation` 有沒有連線關係** → 順序／因果／交集 → 手寫 SVG（`11` §6）；組成／對立／程度 → HTML flex/grid 通常夠
2. 用 SVG 時，規格卡要**補上 `viewBox` 與節點座標**才算交接完成，只寫「箭頭鏈」等於沒交接
3. `focus` 翻成具體手段：只有焦點節點有強調色 ＋ 只有它有 `❗`／較粗邊框，**不要同時用三種手段強調同一個東西**
4. 交付時把 `11` §6 的量測腳本一起附上——**手寫 SVG 沒跑過量測就等於沒做完**

補完座標的規格卡片段：

```yaml
svg:
  viewBox: "0 0 1720 420"
  nodes:
    - { x: 120,  y: 160, w: 400, h: 140 }
    - { x: 660,  y: 160, w: 400, h: 140 }   # focus
    - { x: 1200, y: 160, w: 400, h: 140 }
  connectors: 直線 ＋ 共用 marker（id 要每頁獨立，見 11 §6 的 document scope bug）
```

### 翻給 Gamma／Napkin（自動生成）

順序很重要：**結論句 → 逐字節點 → 禁止清單**。把禁止放最後，因為這類工具容易只吃前半段（依實測調整）。

> 請做一頁投影片。
>
> **這頁的結論是**：漏單不是人員疏失，是三個系統之間沒有交接點。
>
> **視覺形式**：由左到右的三節點因果鏈，節點之間**要有連線**表達「流向」。
>
> **以下三個節點文字請逐字使用，不要改寫、不要潤飾、不要加字**：
> 1. 業務系統收單
> 2. 人工轉貼到 ERP
> 3. 倉儲系統出貨
>
> **視覺重點只有一個**：第 2 個節點。請只有它使用強調色，第 1、3 個用灰階。
>
> **請不要做的事**：不要把三個節點做成等大小、等權重的並列卡片；不要加圖示；不要加圖例；不要加任何裝飾性線條或幾何色塊。

產出後**必檢兩件事**（這兩件最常失守）：三個節點是不是變成等權？連線有沒有真的畫出來？沒過就把 `forbid` 那段再貼一次，通常第二輪會修正。

### 翻給 Canva／PPTX（人工排）

給執行的人一張 checklist，附具體數值而不是形容詞：

- 版型：2 左文右圖，文字欄 55%／視覺欄 45%
- 網格：12 欄，左右邊界留白 = 畫布寬 5%
- 標題基線：與前後頁對齊同一條（`12` §2）
- 內文字級：≥ 畫布高 1/30（1920×1080 → ≥ 36px，見 `06`）
- 顏色：強調色只出現在焦點節點；其餘用中性階 3 階
- 節點文字：從規格卡複製，**不要改字**

## 三、交接時最常掉的四樣東西

這四個是實測反覆發生的，交接後**逐項對回規格卡檢查**。

**1. 逐字稿被改寫成「更順」的說法。**
「人工轉貼到 ERP」被改成「跨系統資料整合作業」——後者聽起來專業，但把「人在複製貼上」這個唯一有說服力的事實藏起來了。斷言愈刺，愈容易被潤掉。防守：`nodes` 標「逐字」，交接後逐字比對。

**2. 強調點被平均化。**
規格寫了 `focus`，工具還是做成三個等大卡片——因為 `focus` 沒有被翻成具體手段。防守：交接時把 `focus` 寫成「只有它有 X，其餘沒有」，X 是單一手段。

**3. 幾何訊息被抹平。**
`geometry` 欄位存在的唯一理由。「前期 4 天、後期 5 個月」交出去會變成等距時間軸，**等距等於用版面否定你的論點**（`11` §2）。防守：寫死比例並標「不可等距」，例如 `geometry: 4天:5個月 ≈ 1:38，右段必須明顯壓縮，不可等距`。

**4. 顏色語意退化成裝飾。**
規格寫「用藍色」→ 工具當成品牌色到處鋪。要寫的是**分工**：`藍 = 我方方案 / 灰 = 現狀 / 只有這兩色帶語意，其餘皆中性`。防守：`color` 欄位一律寫「誰是什麼」，不要只寫色名（`12` §5）。

## 四、範例指令

### 產出整份的規格卡

> 我們已經確定了大綱與每頁要回答的問題。請幫我把它轉成頁面規格卡，每頁一張，欄位固定為：page／question／message／relation／form／layout／nodes／focus／color／geometry／script／forbid。
> 規則：`message` 必須是一句可被反駁的斷言，不能是「介紹 X」這種描述；`relation` 只能從 順序／組成／對立／因果／交集／程度／單一 七種裡選一個；`nodes` 寫逐字文案不要寫「等等」；每頁 `focus` 只能有一個。
> 如果某頁的 `relation` 你判斷是「並列且彼此無關」，先停下來告訴我，我們檢查那頁是不是內容還沒想清楚。

### 補上 SVG 座標（交給程式產出前）

> 這是第 7 頁的規格卡。請幫我補上 `svg` 區塊：viewBox 尺寸、每個節點的 x/y/w/h、連線路徑。
> 條件：畫布 1720 寬；三節點水平排列，間距相等；焦點節點要比另外兩個高 20px 以表達強調；連線用共用 marker，marker id 要包含頁碼避免跨頁衝突。
> 算完座標後，請一併給我量測用的檢查腳本，我要在瀏覽器確認沒有疊字或越界。

### 檢查產出有沒有背離規格

> 這是第 7 頁的規格卡，這是產出的結果（截圖／code）。請逐欄比對，只回報**背離的項目**，不要複述做對的部分。
> 特別檢查四件事：(1) 節點文字有沒有被改寫 (2) focus 是不是唯一且真的被強調 (3) geometry 的比例有沒有被抹平成等距 (4) 顏色有沒有從語意退化成裝飾。

## 給使用者的引導原則

1. **規格卡是給工具看的，不是給人看的。** 使用者若嫌欄位煩，用最小可用版本（`message`／`relation`／`nodes`／`focus`）也行——但要說清楚省掉的欄位就是產出工具的自由發揮空間。
2. **控制力愈低的工具，`forbid` 要愈長。** 寫 code 可以精確指定，所以禁止清單可短；Gamma 這類只能引導，禁止清單反而是主要的控制手段。
3. **不要在規格卡裡塞美學形容詞。** 「簡潔大方」「有科技感」對任何工具都不可執行。能寫成數值或「只有 X 有 Y」的句子才有用。
4. **交接後一定要對回去檢查。** 這一步最常被省略，而上面四樣東西每次都會掉一兩樣。檢查時只看背離項，不要重讀全部。
5. **規格卡填不出來的頁，是內容問題不是格式問題。** 特別是 `message` 填成「介紹 X」、`relation` 填不出來的頁——那頁通常還沒想清楚，回 `02-research-and-argument.md`，不要硬填欄位交出去。
