# 視覺形式選擇與概念圖解庫

## 這份文件解決什麼問題

`06`（版面雷區）和 `07`（圖表雜訊）都是**診斷工具**——告訴你什麼是壞的。這份是**生成工具**：給定一段內容，它該長成什麼樣子。

商業簡報的說服力，很大一部分不是靠文字堆疊，而是**靠圖解引導觀眾的理解路徑**。一張對的圖能在 3 秒內傳達一段話要講 30 秒的邏輯關係。

---

## 一、核心判斷：先問邏輯關係，再選形式

**不要問「這頁要配什麼圖」，要問「這段內容的邏輯關係是什麼」。**

| 內容的邏輯關係 | 該用的視覺形式 | 常被誤用成 |
|---|---|---|
| 順序、流程、階段 | 步驟條、時間軸、循環圖 | 條列 |
| 組成、結構、層次 | 階層樹、堆疊層、金字塔 | 條列 |
| 對立、比較、取捨 | 雙欄對照、2×2 象限 | 條列 |
| 因果、推導 | 箭頭鏈、金字塔 | 條列 |
| 交集、關係、網絡 | 韋恩圖、關聯圖、中心輻射 | 條列 |
| 程度、範圍、篩選 | 光譜、漏斗、地圖 | 條列 |
| 單一結論、單一數字 | 大字報、數字英雄 | 條列 |

看出規律了嗎——**預設值永遠是條列**。

但條列只適合一種情況：**並列、彼此無關、順序無所謂**的資訊。真正符合這個條件的內容其實很少。

> **關鍵心法：大部分的條列，都是在掩蓋一個沒被畫出來的結構。**
>
> 看到一頁有 4–5 個項目時，先問一句：這些項目之間**有沒有關係**？
> 有先後 → 流程圖。有大小包含 → 階層圖。有對立 → 對照。有交集 → 韋恩圖。
> 真的完全平行無關 → 才留條列。

## 二、概念圖解庫（六大類）

這裡指的是**概念圖解**（diagram），不是數據圖表（chart）。數據圖表請看 `07`。

商業簡報八成的視覺需求落在這六類。

### 1. 流程／順序型

| 圖型 | 用在什麼內容 | 元素上限 | 注意 |
|---|---|---|---|
| **線性步驟條** | 有明確先後的階段（導入流程、方法論步驟） | 3–5 步 | 超過 5 步就分兩層或拆頁 |
| **循環圖** | 會重複的循環（PDCA、飛輪、成長迴圈） | 3–5 節點 | 一定要讓人看出「會繞回去」 |
| **時間軸** | 里程碑、roadmap、發展史 | 4–7 點 | 時間間距要按比例，不要平均分配造成誤導 |
| **泳道圖** | 跨部門流程，需要交代「誰負責哪一段」 | 3–4 條泳道 | 對內流程說明專用，對外提案通常太細 |

### 2. 結構／組成型

| 圖型 | 用在什麼內容 | 元素上限 | 注意 |
|---|---|---|---|
| **階層樹** | 組織架構、產品線分類 | 3 層 | 第 4 層開始沒人看得清 |
| **堆疊層** | 技術架構、能力層級（底層支撐上層） | 3–5 層 | 層與層要有明確的「誰支撐誰」 |
| **金字塔** | 優先順序、數量遞減（漏斗式的人數/客群） | 3–4 層 | 底寬頂窄要有意義，不要只是好看 |
| **同心圓** | 核心到外圍、影響範圍擴散 | 3 圈 | 圈與圈的關係要說得出來 |

### 3. 比較／對立型 ← 商業提案最常用

| 圖型 | 用在什麼內容 | 元素上限 | 注意 |
|---|---|---|---|
| **雙欄對照** | Before/After、現況 vs 導入後、我們 vs 競品 | 2 欄 × 3–5 列 | 兩欄的比較維度必須一致，否則是偷換概念 |
| **2×2 象限** | 定位、優先排序（重要/緊急、成本/效益） | 4 格 | 兩個軸必須是**獨立**的維度，否則所有點會擠成一條線 |
| **天秤／蹺蹺板** | 取捨關係（速度 vs 品質） | 2 邊 | 適合強調「不能兩全」 |
| **評分表** | 多方案 × 多維度比較 | 4 方案 × 5 維度 | 一定要標出勝出的那格，不要讓觀眾自己算 |

### 4. 關係／連結型

| 圖型 | 用在什麼內容 | 元素上限 | 注意 |
|---|---|---|---|
| **韋恩圖** | 交集、共通點 | **最多 3 圈** | 4 圈以上人腦無法處理，改用表格 |
| **關聯網絡** | 生態系、利害關係人地圖 | 7 節點 | 線太多會變毛球，只畫關鍵連結 |
| **中心輻射** | 平台與周邊、核心產品與延伸 | 中心 1＋外圍 5–6 | 適合說明「我們是樞紐」 |
| **因果鏈** | 邏輯推導（因為 A 所以 B 所以 C） | 3–4 環 | 箭頭方向要一致，不要有回頭箭頭 |

### 5. 範圍／定位型

| 圖型 | 用在什麼內容 | 元素上限 | 注意 |
|---|---|---|---|
| **光譜／滑桿** | 程度、成熟度、光譜上的位置 | 1 條軸 | 標出「我們在哪」和「要往哪走」 |
| **漏斗** | 轉換率、層層篩選 | 3–5 層 | 各層寬度要反映真實比例 |
| **旅程地圖** | 客戶旅程、使用者體驗歷程 | 4–6 階段 | 每階段標出情緒或痛點才有價值 |

### 6. 單一焦點型

| 圖型 | 用在什麼內容 | 注意 |
|---|---|---|
| **大字報** | 一句結論、一個主張 | 整頁只有這句話，不要再配佐證 |
| **數字英雄** | 單一關鍵數據 | 一定要附比較基準（見 `07` 數字有感化） |
| **引言卡** | 客戶原話、專家背書 | 要有出處與人名，否則沒有可信度 |

## 三、圖示引導：讓圖自己帶著觀眾走

畫出圖只完成一半。**圖的價值在於引導觀眾的理解順序**——如果觀眾看著圖不知道從哪開始，那張圖就失敗了。

### 四個引導技巧

1. **設計閱讀動線**：中文與英文讀者的預設掃視路徑是「左上 → 右下」。把起點放左上、結論放右下，符合本能。若要打破（例如中心輻射圖），就必須用其他手段強制引導。

2. **編號 > 箭頭 > 位置**：引導力量由強到弱。流程一定要編號（①②③），不要只靠位置暗示順序。

3. **一張圖只有一個焦點**：用顏色深淺製造主從。要強調的那格給強調色，其他全部退成中性灰。**如果每個元素都被強調，等於沒有強調。**

4. **標註 > 圖例**：直接把說明標在圖上，不要放圖例讓觀眾來回對照。每一次「看圖 → 看圖例 → 回頭看圖」都是認知成本，而台上你不會給他們這個時間。

### 簡化紀律

- **元素上限 5–7 個**。大腦同時處理視覺資訊的容量有限，超過就會啟動省力模式直接放棄。
- **對稱 = 平等，不對稱 = 有主從**。如果三個方案裡你有推薦的那一個，就不要畫成三個一樣大的框。
- **什麼時候不該畫圖**：內容本來就是並列無關的清單、或整頁只有一句話——硬畫圖反而是裝飾氾濫（見 `06` 誤區 6）。

## 四、照片、插圖、圖示、純字：怎麼選

| 你的需求 | 用什麼 | 為什麼 |
|---|---|---|
| 建立情緒、真實感、現場感 | **真實照片** | 專案現場照、自己拍的畫面，比任何 AI 生成圖都有說服力 |
| 抽象概念、沒有實物可拍 | **插圖／圖解** | 流程、架構、關係——這些拍不出來 |
| 標示類別、快速辨識 | **圖示（icon）** | 必須成套使用，規格見下方第五節 |
| 邏輯推導、精確資訊 | **文字＋圖解** | 精確性是文字的強項，不要硬轉成圖 |
| 一個結論 | **純字（大字報）** | 最強的視覺，往往就是一句話佔滿整頁 |

### 圖片疊字的可讀性

商業簡報常見的翻車點——照片上直接放白字，結果照片亮的地方字就消失了。

- 加**半透明遮罩（scrim）**或漸層，讓文字區塊底下暗下來
- 文字與底色對比至少 **4.5:1**
- 不要把字疊在照片細節複雜的區域（人臉、樹葉、群眾）
- 更安全的做法：文字放在照片旁邊的純色區塊，不要疊

## 五、圖示系統（icon set）

> 注意術語：第三節的「圖示引導」講的是**圖解**如何引導閱讀動線；這一節講的是 **icon**——那些代表類別的小符號。兩件不同的事。

### 為什麼這是專業感的分水嶺

**最快讓一份簡報看起來業餘的方式，就是混用不同來源的圖示。** 觀眾不會說出「這些圖示風格不一致」，但整份的質感就是會垮——因為大腦會偵測到這些符號不屬於同一個系統。

反過來說，顧問公司那種「看起來很高級」的簡報，很大一部分不是版面多精巧，而是**圖示成套、規格統一**。這是投報率很高、但幾乎不需要美感天分的一項投資。

### 必須統一的四個變數（缺一個就會露餡）

| 變數 | 要求 |
|---|---|
| **填充方式** | 線性（outline）／實心（solid）／雙色（duotone）——**整份只選一種** |
| **線寬** | 所有圖示同一個 stroke-width；自繪 SVG 就固定數值不要各頁微調 |
| **抽象程度** | 不能一個很寫實、一個很極簡。同一套庫內通常已經一致，跨庫混用就會壞 |
| **轉角** | 圓角或直角要一致，並跟簡報整體的 radius 呼應 |

### 尺寸階與對齊

- **三階就夠**：內文旁 32–40px／卡片標題 48–64px／章節主視覺 120px 以上。
- **視覺補償**：圓形圖示看起來會比同尺寸的方形小，圓形要放大約 10% 才視覺等重。
- 圖示與文字並排時，對齊**文字的光學中心**，不是對齊頂部。
- 同一列的多個圖示，**邊界框要等寬**（即使圖形本身寬窄不同），否則後面的文字會參差。

### 顏色紀律

- **圖示預設用中性階，不要用強調色**——除非它就是那頁的焦點。一頁 6 個彩色圖示等於沒有焦點（呼應 `12` 的強調色紀律）。
- **單色圖示＋中性階，比多彩圖示專業。** 多彩圖示看起來熱鬧，但會讓版面失去層級。
- **徽章式 vs 裸圖示**：把圖示放進圓形／方形色塊裡叫「徽章」，適合編號流程與並列卡片，也是顧問風簡報質感的來源之一。**整份選一種，不要混用。** 用徽章時，所有徽章直徑與底色階要統一。

### 什麼時候不該放圖示

最常見的濫用：**每個 bullet 前面都加一個圖示**。那不是設計，是填空。

判斷法：**拿掉這個圖示，理解會變慢嗎？** 不會 → 拿掉（呼應 `06` 誤區 6：每加一個視覺元素前，先問它有沒有在幫內容說話）。

還有一個硬限制：**圖示適合具體名詞，不適合抽象動詞。**

- 有公認符號：資料庫、文件、時間、人、地點、金錢、警示
- 沒有公認符號：「協同」「賦能」「轉型」「洞察」——硬找一個反而增加解讀成本，不如就用文字

### 來源一致性

- **一份簡報只從一套圖示庫取用。** 找不到需要的那個圖示時，用該套庫裡**最接近的**，不要跨庫去找那個「完美的」——完美的那一個會毀掉整套的一致性。
- **不要混 emoji 和 icon。** 這是最常見的翻車：內文用了成套線性圖示，標題卻放一個 emoji，兩者的抽象程度與色彩邏輯完全不同。
- 程式產出（open-slide／SVG）時：固定 `viewBox` 與 `strokeWidth`，用同一組參數產生所有圖示。

### 自檢清單

- [ ] 全份是同一種填充方式（線性／實心／雙色）？
- [ ] 線寬一致？
- [ ] 沒有 emoji 混進成套圖示裡？
- [ ] 圖示顏色是中性階，只有真正的焦點才用強調色？
- [ ] 有沒有純裝飾、拿掉也不影響理解的圖示？
- [ ] 有沒有替抽象概念硬塞一個看不懂的圖示？
- [ ] 徽章式與裸圖示有沒有混用？

## 六、用程式畫圖時：手寫 SVG 座標圖

這一節是給**用程式產出投影片**的情境（open-slide／HTML deck／React）。同樣一張概念圖，用 HTML flex/grid 排，跟用手寫 SVG 座標畫，成品差距很大。

### 什麼時候該改用 SVG

| 用 HTML flex/grid | 改用手寫 SVG |
|---|---|
| 並列卡片、雙欄對照、表格 | 流程／扇出／收攏／因果鏈／循環／非等距時間軸 |
| 元素間沒有連線關係 | **元素之間要用線連起來**——這是最強的判斷依據 |
| 位置由內容長度決定就好 | 位置必須精確（要對齊、要成比例、要交錯避讓） |

**核心差別**：flex 的位置是「算出來的」，你只能間接影響；SVG 的位置是「寫死的」，完全可控。所以凡是「兩個元素必須對齊」「這條線必須指到那個框的底邊」「這段距離必須比那段長三倍」，flex 都做不到，SVG 才行。

反過來說，SVG 沒有自動避讓——**所有座標都要自己算，算錯就會疊字**（見下方量測紀律）。

### 六個核心技巧

1. **`viewBox` 建立虛擬畫布**
   `viewBox="0 0 1720 600"` 後，內部所有座標都是這個座標系的單位，跟實際渲染尺寸無關。搭配 `width:100%; height:100%` 就能自動縮放到任何投影尺寸，不會跑版。
   *頂部或左側被裁到時，直接改 viewBox 原點留白（`viewBox="0 -14 1720 614"`），比逐個挪座標省事。*

2. **貝茲曲線做扇出與收攏**
   `<path d="M 640,240 C 700,240 720,80 780,80" />`——`C` 是三次貝茲。一對多分流時，**用直線會交叉打結，用曲線才能優雅分開再優雅收攏**。控制點取「起點正右方」與「終點正左方」，曲線就會平滑地水平進出。

3. **`<marker>` 定義一次、全圖共用**
   ```svg
   <defs><marker id="myArr" markerWidth="10" markerHeight="10" refX="8" refY="4" orient="auto">
     <path d="M0,0 L8,4 L0,8 Z" fill="…" /></marker></defs>
   <line … markerEnd="url(#myArr)" />
   ```
   所有箭頭形狀、大小、角度自動一致（呼應第五節的圖示一致性）。

4. **疊兩個 `<rect>` 做色條卡片**
   一個大的圓角矩形當卡片，再疊一個窄的實色矩形當色條（頂部橫條或左側直條）。這樣 SVG 裡的節點就能跟頁面上其他 HTML 卡片長得一樣，同一份簡報不會出現兩種視覺語言。

5. **用顏色編碼層級，不要用文字解釋層級**
   例如：紫＝總指揮、藍/綠/琥珀＝三個並列的執行者、綠＝人工把關。看顏色就分出角色，省掉圖例（呼應第三節「標註 > 圖例」）。

6. **讓幾何本身承載訊息**
   這是 SVG 最大的優勢，也最常被浪費：
   - 時間軸如果「前期4天、後期5個月」，就**不要畫成等距**——等距等於用版面否定你的論點。按真實比例壓縮，長度差本身就是證據。
   - 「以前要等3-6個月／現在同一天」，就讓「以前」佔滿全寬、「現在」擠在最左15%，**右邊那片留白就是訊息**。
   - 階梯比喻就真的畫成逐階升高，不要畫成四條等高橫條。

### 量測紀律（血淚教訓，不要跳過）

SVG 沒有自動避讓，**目視檢查一定會漏**。每畫完一張圖，在瀏覽器跑一次量測：

```js
// 抓出所有 text 的重疊與越界
document.querySelectorAll('main svg[viewBox]').forEach(svg => {
  const [vx,vy,vw,vh] = svg.getAttribute('viewBox').split(/\s+/).map(Number);
  const boxes = [...svg.querySelectorAll('text')].map(t => {
    const b = t.getBBox();
    return { s: t.textContent.slice(0,18), x:b.x, y:b.y, w:b.width, h:b.height };
  });
  // 兩兩比對重疊
  for (let i=0;i<boxes.length;i++) for (let j=i+1;j<boxes.length;j++) {
    const a=boxes[i], b=boxes[j];
    const ox = Math.min(a.x+a.w,b.x+b.w) - Math.max(a.x,b.x);
    const oy = Math.min(a.y+a.h,b.y+b.h) - Math.max(a.y,b.y);
    if (ox>3 && oy>3) console.warn('重疊', a.s, b.s, ox, oy);
  }
  // 越界
  boxes.filter(b => b.x<vx-2 || b.y<vy-2 || b.x+b.w>vx+vw+2 || b.y+b.h>vy+vh+2)
       .forEach(b => console.warn('越界', b.s, b.x, b.y));
});
```

常見的兩種座標錯誤：
- **同一水平帶塞了兩組文字**：例如軸線下方同時放「說明文字」和「里程碑標籤」，x 範圍一重疊就疊字。解法：讓一整條水平帶只屬於一種內容（里程碑全部移到軸線上方、說明帶獨佔下方）。
- **文字錨點在邊界附近**：`textAnchor="middle"` 的文字，實際 bbox 會往左右各長出半個字串寬度，靠邊的節點很容易超出 viewBox。

### 一個真實的 bug：`<marker>` 的 id 是 document scope

SVG 的 `url(#id)` 參照是**整份文件的作用域**，不是單一 `<svg>` 內。所以：

> A 頁的 `<svg>` 定義了 `#myArr`，B 頁的 `<svg>` 寫 `markerEnd="url(#myArr)"` 卻沒自己的 `<defs>`。開發時兩頁同時掛在 DOM（縮圖列）看起來正常，一旦只 mount 當前頁，**B 頁的箭頭頭會整排消失，線還在**。

**規則：每個 `<svg>` 自帶自己的 `<defs>`，marker id 加頁面前綴避免撞名。** 或抽成共用的 marker 元件重複掛。

## 給使用者的引導原則

- 使用者問「這頁配什麼圖」時，**先反問邏輯關係**，不要直接推薦圖型。形式是從關係推導出來的。
- 看到一頁 4–5 個條列項目，主動檢查它們之間有沒有結構——這是最高頻、也最容易提升質感的改動。
- 誠實面對「不用畫圖」的情況。裝飾性的圖解比沒有圖更糟（呼應 `06` 誤區 6：每加一個視覺元素前，先問它有沒有在幫內容說話）。
- 元素超過 7 個時，不要硬塞——建議拆頁或移附錄，不要縮小字級硬擠（呼應 `06` 刪減紀律）。
- **看到圖示風格混用（尤其 emoji 混進成套 icon）就主動指出。** 這是質感垮掉最常見也最好修的單一原因，而使用者通常說不出哪裡怪。第五節的自檢清單可以直接照著跑。
- 使用者想要「顧問公司那種質感」時，先確認的不是版面，而是**圖示是否成套＋是否用徽章統一**——那是那種質感的主要來源，跟美感天分無關。
- **用程式產出簡報時，看到「元素之間需要用線連起來」就建議改手寫 SVG**（第六節）。flex 排不出精確對齊與比例，硬排的結果是線不對齊、長度不成比例，版面反而否定論點。
- **手寫完 SVG 一定要跑 `getBBox()` 量測，不要靠目視。** SVG 沒有自動避讓，疊字與越界只有量測抓得到；每個 `<svg>` 也必須自帶 `<defs>`，否則 marker 會因為 id 是 document scope 而在單頁 mount 時消失。
