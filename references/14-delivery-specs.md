# 交付規格：畫布比例、安全區、中文字型、PDF 輸出

## 這份文件解決什麼問題

前面 13 份文件都在處理「內容對不對、視覺對不對」。這份處理最後一哩：**檔案交出去之後，在別人的機器、別人的投影機上還是不是同一份東西。**

這一哩最常出的三種事故：

1. **比例錯**：做 16:9，現場投影機是 4:3 → 左右被裁，或整份縮小到中間一小塊。
2. **字掉了**：交出 PPTX，對方電腦沒有你的字型 → 中文變成新細明體、行距全跑掉，或罕用字變成 □。
3. **PDF 壞了**：逐步揭露的頁在 PDF 裡疊成一團；深色底列印出來看不清。

這些都不是美感問題，是**可以事前驗證的技術問題**。全部都有具體檢查方法。

**什麼時候用**：使用者說「簡報做好了」「要寄給對方」「要印出來」「明天要上台」的時候。這也是提醒他還有講稿與 Q&A 的時機（見 `09`）。

---

## 一、16:9 還是 4:3：先問設備，不要問喜好

**判斷依據是投影設備，不是美感偏好。**

| 場合 | 預設比例 | 為什麼 |
|---|---|---|
| 線上會議（Teams／Zoom／Meet） | 16:9 | 分享畫面就是 16:9，4:3 兩側會留黑邊 |
| 自備筆電 ＋ 現代投影機／大電視 | 16:9 | 現在的機器幾乎都是 16:9 |
| 客戶／學校／老會議室的固定投影機 | **先問，問不到就 4:3** | 這是唯一還會遇到 4:3 的地方 |
| 只給人自己讀（不投影） | 16:9 | 螢幕閱讀為主 |
| 要印成紙本講義 | 4:3 更接近 A4 | 16:9 印 A4 上下會空一大條 |

要問的一句話：**「現場是用我的筆電接投影機，還是用貴公司固定的設備？投影出來是寬的還是方的？」** 對方答不出來時，請他拍一張現場投影畫面。

### 如果真的無法事先確認

用 **4:3 安全區策略**：畫布做 16:9，但把**所有文字與關鍵元素放進中央 4:3 的範圍內**，只讓背景、色塊延伸到左右兩側。這樣 4:3 播放被裁掉的只有背景。

代價是可用寬度變窄（16:9 畫布的中央 4:3 區約只有 75% 寬），版面會比較擠——所以這是保險做法，不是首選。能問清楚就別用。

### 不要做的事

**不要把做好的 16:9 直接改成 4:3**（或反之）。改比例會讓所有版型的比例關係、標題基線對齊（`12` §2）全部跑掉，通常比重排一次更慘。真的要兩用，就準備兩份輸出。

## 二、安全區：邊界留白與下緣禁區

投影機有 overscan，會議室有人頭，線上會議有工具列和字幕條。這些都會吃掉畫面邊緣。

| 區域 | 留多少 | 為什麼 |
|---|---|---|
| 左右邊界 | ≥ 畫布寬 **5%** | overscan 裁切；也是 `12` §2 網格的邊界 |
| 上緣 | ≥ 畫布高 **5%** | 同上 |
| **下緣** | ≥ 畫布高 **8–10%**，**不放任何要讀的字** | 前排人頭遮擋、線上會議字幕條、視訊小窗 |

下緣禁區是最常被違反的一條——頁碼、來源註記放那裡沒問題（沒人非讀不可），但**結論句、圖表的軸標籤放下緣，等於現場有一半人看不到**。

字級與觀眾距離的規則見 `06-layout-pitfalls.md`（內文 ≥ 畫布高 1/30），投影環境的明暗與底色選擇也在 `06`，這裡不重複。

## 三、中文字型：掉字與跑版

這是中文簡報特有、而且**最容易在最後一刻炸掉**的問題。分成兩種故障：

- **跑版**：對方機器沒有你的字型 → 系統換成預設字型（Windows 常換成新細明體、Mac 換成蘋方）→ 字寬變了 → 行數變多 → 版面全垮。
- **掉字（豆腐字 □）**：字型檔本身缺那個字 → 顯示成空框或問號。中文最常在**人名罕用字**（堃、喆、羱）、**異體字**、**日文漢字**上出事。

### 各種格式的實際狀況

| 交付格式 | 字型會不會跟著走 | 實務建議 |
|---|---|---|
| **PDF** | ✅ 會（字型子集嵌入是預設行為） | **交付的首選。** 對外寄送、上台備份一律準備 PDF |
| **PPTX（Windows PowerPoint）** | ⚠️ 要手動開嵌入 | 選項 → 儲存 → 勾「在檔案中嵌入字型」。中文字型嵌入後檔案會變很大 |
| **PPTX（Mac PowerPoint）** | ❌ 嵌入支援不完整 | 不要指望。改交 PDF，或只用系統內建字型 |
| **Keynote** | ⚠️ 對方要有 Keynote | 不適合對外交付 |
| **Google Slides** | ✅ 字型在雲端 | 但只能用它字型庫裡的中文字型 |
| **HTML deck（open-slide 等）** | 看 webfont 怎麼載 | 見下方「從瀏覽器輸出 PDF」 |

### 三個降低風險的做法（依保險程度排序）

1. **交 PDF。** 最有效，一步解決跑版與掉字。缺點是對方不能改。
2. **只用作業系統內建的中文字型。** Windows＋Mac 都有的實務交集很小，最安全的是**思源黑體／Noto Sans CJK**（免費、可自行安裝、字集完整），其次是微軟正黑體（Windows 有、Mac 沒有）。**不要用你自己買的字型**去交 PPTX。
3. **把出事的頁轉成圖片。** 標題頁、大字報頁、手寫 SVG 圖解頁——這些頁字型一換就毀，轉成 PNG 貼回去最穩。缺點是文字不能再選取／編輯。

### 怎麼驗證（不要靠目視相信）

**驗 PDF 有沒有嵌入字型**——選一段中文，**能被選取、能被搜尋到**，就是有嵌入的文字（不是圖片）。要看得更確定，用 poppler 的 `pdffonts`：

```bash
pdffonts 你的簡報.pdf
```

每一列的 `emb` 欄位要是 `yes`。有 `no` 的那個字型就是會在別人機器上換掉的。

**驗有沒有掉字**——把整份的**所有中文字**（特別是人名、地名、專有名詞）貼進一個純文字檔，用目標字型渲染一次看有沒有 □。最直接的做法是在簡報裡搜尋，或請 AI 從內容中挑出罕用字清單再逐個確認。

**驗跑版**——**在一台沒有裝該字型的機器上開一次**。這是唯一可靠的驗法，沒有替代方案。沒有第二台機器時，退而求其次：把字型暫時停用後重開檔案。

## 四、PDF 輸出

### 從瀏覽器／HTML deck 輸出

三個必做的設定：

1. **等字型載完才印。** webfont 還在下載時觸發列印 → 整份用 fallback 字型輸出。程式化輸出前要等 `document.fonts.ready`；手動列印時先完整捲過一遍再按 Ctrl/Cmd+P。
2. **`@font-face` 用本機字型檔，不要用 CDN。** 離線環境、CDN 被擋、網路慢都會導致 fallback。這也是為什麼**交付當天不要依賴任何線上資源**。
3. **列印設定**：紙張尺寸設成畫布比例（不是 A4）、邊界設 0、**關掉「頁首及頁尾」**（不關會在每頁印上網址和日期），背景圖形要打開（不打開深色底會變白底）。

```css
@page { size: 1280px 720px; margin: 0; }
@media print {
  .slide { page-break-after: always; break-inside: avoid; }
}
```

若使用 `open-slide`，先確認它自己有沒有內建的 export／print 指令，有就用它的——比自己接瀏覽器列印可靠。沒有再走上面的路徑。

### 逐步揭露的頁怎麼處理

`06` 建議的逐步揭露（一頁分幾段出現）在 PDF 裡**會全部疊在同一頁**，變成一團看不懂的東西。兩個選擇：

- **給讀者的版本**：取消揭露，讓那頁一次顯示完整內容（通常也更適合閱讀）
- **給自己上台備份的版本**：每個揭露步驟輸出成一頁（PDF 頁數會比投影片頁數多），這樣按 PDF 也能照原節奏講

**要做哪一種，取決於這份 PDF 是給誰的**——這是 `01` 的 presented vs read 分流在交付層的延伸。

### 深色底 deck 的紙本問題

深色底在投影時效果好，**印出來會吃掉大量墨、而且細字會糊**。如果對方會印，另做一份淺底的讀者版。不要交深色底 PDF 又叫對方「印的時候自己調」。

## 五、交付前 checklist

上台或寄出前逐項確認。前四項是「會不會炸」，後三項是「炸了怎麼救」。

**會不會炸**

- [ ] 比例對：跟現場設備一致（已確認過，不是假設）
- [ ] 字型驗過：PDF 的 `emb` 全部 `yes`；或已在沒裝字型的機器上開過一次
- [ ] 掉字驗過：人名、專有名詞、罕用字沒有 □
- [ ] 安全區：下緣 8–10% 內沒有必讀的文字

**炸了怎麼救**

- [ ] **PDF 備份**：不管主要交付什麼格式，一定另存一份 PDF 帶在身上
- [ ] **離線可用**：字型、圖片、影片都在檔案裡或同一個資料夾，不依賴網路
- [ ] **檔名帶日期與版本**：`專案名_對象_20260729_v3.pdf`。「最終版_final_真的最終.pptx」這種檔名在對方信箱裡就是災難

**現場**

- [ ] **提早到場試投**（`06` 已強調）：試投時就是在驗上面所有項目——比例、字型、深色底在那台投影機上的實際亮度

## 六、範例指令

### 決定交付規格

> 我這份簡報是 [對客戶提案／對內匯報]，現場是 [自備筆電接投影機／對方固定設備／線上會議]，對方 [會／不會] 事後自己讀，[會／不會] 印出來。
> 請幫我決定：畫布比例、要交付哪些格式（各幾份、給誰）、以及我現在該做哪些驗證。如果我提供的資訊不足以判斷比例，直接告訴我要去問對方什麼問題，不要幫我猜。

### 找出字型高風險頁

> 請掃過我這份簡報的所有文字，列出**中文罕用字、異體字、日文漢字、以及非中英文的符號**（例如特殊箭頭、數學符號、emoji），我要確認目標字型有沒有這些字。
> 另外指出哪幾頁一旦字型被替換就會嚴重跑版（例如大字標題頁、字數塞滿的頁、手寫 SVG 圖解頁），這幾頁我考慮直接轉成圖片。

### 規劃兩份輸出

> 這份要同時「上台講」和「寄給對方自己讀」。請幫我規劃兩個版本的差異：哪些頁要在讀者版補上說明文字、哪些逐步揭露要在讀者版取消、附錄在兩個版本要不要都放、深色底要不要另做淺底。
> 不要只回「調整密度」這種籠統建議，請逐頁指出要動哪裡。

## 給使用者的引導原則

1. **比例要問設備，問不到就要對方拍照。** 使用者說「應該是 16:9 吧」時，那是假設不是確認——現場被裁掉半個版面的代價遠大於問一句話。
2. **對外交付一律建議 PDF。** 除非對方明確要編輯，否則 PPTX 交出去就是把跑版風險轉移給對方的機器。
3. **字型問題不能靠目視相信。** 「我這邊看起來很正常」在字型議題上完全沒有參考價值——你的機器有那個字型。一定要用 `pdffonts` 或另一台機器驗。
4. **上台備份的 PDF 不是可選項。** 這是唯一在對方設備、網路、軟體版本都不可控時仍然能講完的東西。
5. **「presented vs read」在交付層要落實成兩份檔案。** 使用者想用一份打天下時，提醒他一定有一邊會壞掉（`01` 已說明），而交付階段正是把它拆成兩份的最後機會。
6. **這一步不要壓縮。** 使用者到這裡通常已經很累、只想寄出去。但前面 13 份文件的努力，全部押在這一哩沒有出事——花 15 分鐘驗證，比現場重做便宜太多。
